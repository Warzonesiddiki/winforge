value name addresses the key's unnamed ("(Default)") value, so `ui-classic-context`'s

no new registry code was needed for the write side (`atlas-restore-old-context-menu` already
used the same pattern).

All four ops are first-class: strict-loader validation (`internal/config`), dry-run previews,
change detection, `IsApplied` verification, audit snapshots, and undo (per-row for the two power
ops; revert-list for `netbios`/`registry_delete_key`, whose previous state is heterogeneous or
unreconstructable and is deliberately not guessed).

### Mapping rules (mechanical, documented in tools/web_catalog_to_engine.py)

- `HKCU\path: Name = 0x…/n` → `registry_set_dword` · `Name = "text"` → `registry_set_string`
- `(Default) = …` → registry op with empty `name` (RegSetValueExW: empty name = default value)
- undo `= default` → `registry_delete` (restores the Windows default)
- undo `<hive>\<key> -> removed` → `registry_delete_key` (recursive; reverts a key the apply side created)
- abbreviated paths (`…`) expanded only via a documented map (Explorer\Advanced, SearchSettings, PrefetchParameters)
- `powercfg /hibernate on|off` → `power_hibernate` true|false (native)
- `powercfg -setacvalueindex SCHEME_CURRENT SUB_PROCESSOR PROCTHROTTLEMIN/MAX n` → `power_processor_state` `{"min"/"max": n}` (native)
- `WMI …SetTcpipNetbios(n)` → `netbios` n (native registry writes)
- other `powercfg`/`powershell` commands are **refused** (elevated-executor allowlist boundary); `bcdedit`/`fsutil` → `command`
- `Service A, B -> Mode` → one `service_start_mode` op per service; `Automatic (Delayed)` → `auto`
- `Scheduled Task: path -> Disabled/Enabled` → `task_disable`/`task_enable`
- risk `expert` → `high` (engine has no expert tier)
- `powercfg -duplicatescheme <GUID>` → matched against native `power_scheme` ops (alias-aware: `ultimate` ≡ `e9a42b02-…`)
