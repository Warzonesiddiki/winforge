| `pwr-hibernation` | `powercfg /hibernate` is not an allowlisted elevated command; the engine prefers native power APIs (a `power_hibernate` op is the future fix). |
| `pwr-processor-mgmt` | `powercfg -setacvalueindex` is not allowlisted; the engine already has native `power.SetProcessorState` — it needs a catalog op type to expose it. |
| `ui-classic-context` | Operates on a registry key's `(Default)` value; the engine registry layer does not support default-value writes. |
| `exp-classic-paint` | The web op is narrative text; Appx lifecycle is handled natively by the engine's bloatware catalog. |

- The JSON write is byte-stable round-trip (`json.dumps(indent=2, ensure_ascii=True)` — verified identical on untouched files).

### Mapping rules (mechanical, documented in tools/web_catalog_to_engine.py)

- `HKCU\path: Name = 0x…/n` → `registry_set_dword` · `Name = "text"` → `registry_set_string`
- undo `= default` → `registry_delete` (restores the Windows default)
- abbreviated paths (`…`) expanded only via a documented map (Explorer\Advanced, SearchSettings, PrefetchParameters)
- `powercfg`/`powershell` commands are **refused** (elevated-executor allowlist boundary); `bcdedit`/`fsutil` → `command`
- `Service A, B -> Mode` → one `service_start_mode` op per service; `Automatic (Delayed)` → `auto`
- `Scheduled Task: path -> Disabled/Enabled` → `task_disable`/`task_enable`
- risk `expert` → `high` (engine has no expert tier)
- `powercfg -duplicatescheme <GUID>` → matched against native `power_scheme` ops (alias-aware: `ultimate` ≡ `e9a42b02-…`)
